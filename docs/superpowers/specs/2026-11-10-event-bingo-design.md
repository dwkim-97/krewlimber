# 모바일 이벤트 빙고

사용자 확정: `/event/bingo`는 비회원과 회원 모두 조 코드로 입장한다. 조마다 획득 숫자·5×5 판·체크 상태를 공유한다. 오프라인에서 번호를 호명하고, 시작 후 번호 체크는 로그인한 회원만 가능하다. 운영진 화면은 `/event/bingo/admin`이다.

기존 Supabase PostgreSQL·자체 회원 인증을 사용한다. 서버의 승인 회원 상태를 기준으로 체크 권한을 판단한다. 비회원은 준비 중 숫자 수집과 판 배치, 진행 중 관람, 종료 후 결과 조회를 할 수 있다. 준비 중 조 코드가 있는 모든 조원이 편집한다. 번호는 1~n, n은 25~1000, 중복 없는 25개를 배치하며 중앙 FREE 칸은 없다. 완성 가능한 줄은 가로 5·세로 5·대각선 2다.

운영진이 n을 정해 이벤트를 만들고 조 이름·자동 발급 코드를 등록한다. 준비 → 진행 → 종료의 단방향 전환이다. 시작은 입력 잠금과 동시에 진행으로 전환한다. 완성 판이 하나 이상 필요하며 미완성 조는 체크·순위에서 제외한다. 관리 화면에서 미완성 현황을 명확하게 확인하고 시작한다. 시작 후 n·숫자 수집·판 배치는 변경하지 못하고 종료하면 체크도 잠긴다. n을 줄일 때 기존 획득 숫자를 삭제하지 않고 범위를 벗어나면 거부한다. 종료 후 새 이벤트는 기존 기록을 보존하며 별도로 생성한다.

번호 상자는 가로 스크롤이며 전체 보기에서는 미획득 번호를 회색 비활성화한다. 획득 번호만 보기 체크박스를 제공한다. 획득 번호를 선택한 뒤 칸을 누르면 배치하며 이미 채운 칸은 해제할 수 있다. 25개 이상 모으면 배치할 수 있다. 정정 중 획득 숫자가 25개 미만이어도 기존 칸을 비울 수 있으며 새 배치는 다시 25개를 모아야 한다. 자동 채우기는 획득 번호만 사용하고 중복을 허용하지 않는다. 진행 중에는 번호 체크·해제가 가능하고 현재 완성 줄을 표시한다. 최종 순위는 완성 줄 내림차순, 동점 공동 순위(1,1,3), 미완성 조는 순위 없음이다.

조 입장에는 HttpOnly·SameSite·운영 HTTPS Secure의 별도 조 세션 쿠키를 사용한다. 조 코드는 관리자에게만 공개하고 일반 상태·순위에는 노출하지 않는다. 입장 실패는 제한하며 조 세션은 만료된다. 회원 로그인은 기존 세션을 사용하고 빙고에서 로그인하면 빙고로 복귀한다. 상태는 DB에서 재조회하며 3초 주기 동기화와 새로고침 복구를 제공한다. 이벤트 전환·번호·판·체크 변경은 트랜잭션 안에서 재검증하며 요청의 이벤트·조 ID와 revision을 함께 확인해 다른 탭의 조 전환과 오래된 저장으로 인한 덮어쓰기를 막는다.

신규 이벤트 테이블은 RLS를 활성화하고 anon/authenticated 직접 접근을 차단한다. 회원 DB·다른 기능은 변경하지 않는다. 운영 마이그레이션·배포는 별도이며 구현은 최신 main aa0a468에서 기능 브랜치·일반 PR로 제출한다.
