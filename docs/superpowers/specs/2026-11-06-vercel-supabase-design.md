# Vercel Hobby + Supabase Free 이전

## 승인된 목표
무료 플랜에서 크루라이머를 운영한다. 기존 화면, 자체 아이디 인증, 회원 승인, 최소 4자 비밀번호 정책을 유지한다. 결제 수단 등록이나 유료 업그레이드는 수행하지 않는다. 도메인 구매는 별도 작업이며 처음에는 vercel.app 주소를 사용한다.

## 구현 방향 (구현자 선택)
- React/Vite 화면을 유지하고 Express API를 Vercel Functions에 연결한다. Next.js 전환은 필요하지 않다.
- SQLite 동기 API를 PostgreSQL 비동기 쿼리로 이전한다. Vercel에는 Supabase transaction pooler를 사용하고 연결 수를 제한한다. 요청 간 공유 트랜잭션을 만들지 않는다.
- PostgreSQL 마이그레이션은 명시적인 관리 명령으로 실행한다. 함수 cold start마다 테이블을 변경하지 않는다.
- DB 자격 증명은 Vercel 서버 환경변수로만 제공한다. VITE_ 변수, 브라우저 번들, Git에 비밀을 넣지 않는다.
- 기존 scrypt 해시와 세션 모델을 유지한다. Supabase Auth로 로그인 방식을 변경하지 않는다.
- 상품 이미지는 private Storage bucket에 저장하고 기존 승인 회원 API를 통해 제공한다. public bucket으로 바꾸지 않는다.
- 권한은 서버에서 검사하고, 애플리케이션 테이블의 anon/authenticated 직접 접근은 차단한다.
- 다중 인스턴스에서 기존 메모리 rate limit이 분산되지 않는 문제를 해결한다. 가입/로그인/복구 제한을 공유 DB에서 관리한다.
- 포인트, 재고, 교환, 취소, 감사 기록은 같은 PostgreSQL 연결의 트랜잭션에서 처리한다. 잔액과 재고 경합은 row lock 및 제약으로 방어한다.
- Origin 검사는 명시한 사이트 주소에 제한한다. Preview 주소를 와일드카드로 신뢰하지 않는다. Vercel 프록시 IP 처리도 별도 검증한다.
- Vercel 업로드 요청 크기 한도와 현재 5MB raw upload 경로를 확인하여 호환되는 크기 제한으로 맞춘다.

## 데이터 처리
로컬 SQLite와 uploads는 보존한다. 계정/이미지를 외부 프로젝트로 옮기기 전 이전 대상을 명시한다. 운영 대상과 Preview 테스트 DB를 공유하여 테스트 데이터로 운영 데이터를 오염시키지 않는다. 세션·복구 토큰은 이전하지 않는다.

## 검증
가입 4자 허용·3자 거부, 로그인·로그아웃, 회원 승인, 비밀번호 변경·복구 및 세션 폐기, 관리자 접근, 공동 타이틀·누적 업적, 공지 검색, private 이미지 접근, 중복 교환·동시 마지막 재고 신청·중복 취소·포인트 정정·실패 rollback을 PostgreSQL에서 검증한다. 전체 테스트, 타입, 린트, 빌드를 통과시킨 뒤 Preview에서 기능을 확인한다.

## 현재 연결 상태
- Vercel 대시보드 로그인 완료. CLI 토큰은 만료 상태.
- Supabase Free / 서울 Nano 프로젝트 wzgjghbmfweyhqazianm 생성 및 TLS 접속 확인. 초기 스키마 적용 완료. 앱은 아직 SQLite를 사용하며 배포 전 API 전환이 필요.
- 무료 조직, 대상 프로젝트, 리전은 로그인 후 실제 계정에서 확인한다. 기존 프로젝트는 임의 재사용하거나 변경하지 않는다.
- GitHub 인증 만료로 원격 PR 생성도 별도 연결 복구가 필요하다.

## 구현 순서
1. 기존 계정과 무료 조직/프로젝트 확인.
2. PostgreSQL 스키마 및 DB 접근 계층 이전, 기존 테스트 포팅.
3. 인증·공지·기록·마켓 API 비동기 전환 및 경합 검증.
4. private Storage 어댑터와 Vercel 진입점·환경변수 템플릿 구성.
5. 새 빈 프로젝트에 스키마 적용 후 Preview 배포·검증.
6. 데이터 이전 범위 확인, 첫 관리자 준비, 프로덕션 전환.
