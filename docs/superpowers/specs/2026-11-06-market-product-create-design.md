# 마켓 상품 등록·수정과 이미지 업로드

승인된 운영진(admin)이 마켓에서 `/market/new`로 상품을 등록하고, 상품 상세의 수정 버튼에서 `/market/:id/edit`로 기존 상품·판매 상태를 변경한다. 일반 회원과 미승인 계정은 페이지와 저장 API에서 차단한다. 판매 중지 상품은 회원 마켓에서 숨기고 운영진 관리 화면에서는 다시 판매할 수 있다. 기존 교환·예약은 유지한다.

## 접근 방식

등록·수정 폼을 복제하면 검증과 저장 동작이 갈라지므로 `ProductForm`을 공유한다. 이미지 주소만으로는 사용자의 파일을 저장할 수 없으므로 기존 Express 서버에 업로드 API와 설정 가능한 파일 저장소를 연결한다. 외부 저장 서비스 연동은 운영 서버를 준비할 때 추가할 수 있다.

상품명·분류·포인트 가격·재고·설명·판매 상태를 기존 계약대로 저장하며 기존 revision 검사를 유지한다. 신규 상품은 명시적 null이고 모든 폼 콜백은 required이다. 성공 후 마켓으로 이동해 완료 메시지를 표시한다. 실패하면 입력을 보존한다. 저장 중 다른 화면으로 이동한 경우 늦은 완료 응답이 현재 화면을 바꾸지 않는다.

## 이미지

파일 선택 시 로컬 미리보기를 보여주고 제거·교체를 지원한다. 기존 이미지 주소 입력도 접어서 보존한다. 실제 업로드는 상품 저장 시 진행하고, 상품 저장 실패 후 재시도하면 이미 업로드한 주소를 재사용한다. 로컬 미리보기 URL은 교체·화면 이탈 시 해제한다.

승인 관리자만 `POST /api/admin/market/images`로 JPG·PNG·WebP 원본을 최대 5MB까지 전송한다. 서버에서 실제 디코딩과 2,500만 화소 제한을 검증하고 긴 변 최대 1800px WebP로 다시 인코딩해 메타데이터를 제거한다. 원본 파일명은 사용하지 않고 내용 해시 파일명과 원자적 파일 교체를 사용한다. 이미지는 승인 회원만 `/api/market/images/:filename`으로 조회하며 캐시하지 않는다.

`UPLOADS_DIR`은 이미지 저장 디렉터리이며 기본값은 SQLite DB와 같은 디렉터리의 uploads이다. 영구 디스크와 백업에 DB·이미지를 함께 포함한다. 운영 서버 주소나 외부 저장 서비스는 아직 연결하지 않는다. DB 스키마와 권한 역할은 추가하지 않는다. 취소되거나 실패한 상품 저장의 업로드 파일은 보존하며, 기존 교환 이미지 보존을 위해 자동 파일 삭제는 하지 않는다.
