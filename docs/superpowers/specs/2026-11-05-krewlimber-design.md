# KREWLIMBER 사내 동호회 사이트 설계

확정일: 2026-11-05
저장소: https://github.com/dwkim-97/krewlimber (비공개)

## 목적과 확정 사항

사내 비공개 클라이밍 동호회를 위한 회원 전용 사이트다. 사용자는 소개 페이지가 필요 없다고 명시했다. 로그인 전에는 내부 회원이나 성과 정보를 공개하지 않는다.

이메일과 OAuth 없이 aiden.dw 같은 사이트 자체 아이디와 비밀번호로 가입·로그인한다. 실제 회사 LDAP 서버에 연결하지 않는다. 가입 후 운영진이 승인해야 회원 목록과 명예의 전당을 조회한다.

## 화면과 접근

- /: 승인된 회원의 내부 베이스캠프. 프로필 바로가기, 회원·명예의 전당 바로가기와 최근 실제 기록을 표시한다. 소개·홍보 콘텐츠를 두지 않는다.
- /login: 첫 진입 화면. 아이디와 비밀번호로 로그인한다.
- /signup: 자체 계정과 가입 신청을 생성하며 역할은 항상 회원, 상태는 승인 대기다.
- /recover: 신원을 확인한 운영진이 전달한 일회용 코드로 비밀번호를 재설정한다.
- /me: 로그인 사용자가 자신의 가입 상태·프로필·비밀번호를 관리한다.
- /members: 승인된 회원만 다른 승인 회원의 프로필을 닉네임·난이도로 검색한다.
- /hall-of-fame: 승인된 회원만 운영진이 등록한 완등·성장·크루 기여 기록을 본다.
- /admin: 승인된 관리자만 회원 승인·반려·정지·권한 변경, 복구 코드 발급, 명예의 전당 등록·삭제를 수행한다.

## 디자인

원본 KREWLIMBER SVG 로고를 수정하지 않는다. 아이보리·검정·라임색, 클라이밍 홀드와 루트 그래픽을 사용한다. 큰 글자와 여백을 쓰되 실제 회원 업무로 바로 연결한다. PC·모바일·키보드 접근을 지원하고, 빈 목록·오류·로딩 상태를 표시한다. 실제로 제공받지 않은 회원이나 성과·통계를 만들지 않는다.

## 구현과 권한

React + TypeScript + Vite, Express + Node SQLite를 사용하며 동일 출처 서버가 화면과 API를 제공한다. 이메일·외부 인증 서비스 연결은 필요 없다. 영구 디스크를 가진 단일 Node 서버를 전제로 한다. Sites의 기본 ChatGPT 로그인 호스팅은 요구와 맞지 않아 사용하지 않는다.

모든 보호 API에 현재 로그인·승인 상태를 검사한다. 역할 변경은 서버만 수행하며 본인 프로필 변경 요청에 권한 필드를 끼워도 무시한다. 마지막 관리자의 강등·정지는 차단한다. 관리자 작업은 DB 변경 이력에 남긴다.

비밀번호는 개별 salt의 scrypt 해시만 저장한다. 무작위 세션과 복구 코드는 해시만 저장한다. 세션 쿠키는 HttpOnly·SameSite, 운영에서는 Secure다. 비밀번호 변경·복구 시 모든 세션을 폐기하고, 정지·권한 변경 시 기존 세션을 삭제한다. 복구 코드는 운영진 신원 확인 후 30분 동안 한 번만 사용할 수 있다. 변경 요청 출처와 로그인 시도 횟수를 검사한다.

첫 관리자는 서버의 대화형 생성 명령에서 신원을 확인한 운영자가 직접 설정한다. 기본 비밀번호·선착순 관리자·GitHub 계정과 웹 계정의 자동 연결은 없다.

## 검증

실제 SQLite·HTTP 테스트로 가입, 입력·중복 검증, 세션 유지·만료·로그아웃, 승인 전 접근 거부, 일반 회원 관리자 접근 거부, 프로필 권한 변조 차단, 정지·비밀번호 변경 후 세션 폐기, 마지막 관리자 보호, 복구 코드 만료·재사용 차단, 명예의 전당 권한·날짜·대상 검증을 확인한다.

타입 검사·warning 0 린트·테스트·운영 빌드, PC·모바일 브라우저 확인 후 /simplify와 Codex 리뷰(최대 2회)를 수행한다. 코드 작업은 기능 브랜치에서 하고 비어 있는 초기 저장소의 bootstrap 브랜치를 기준으로 PR을 제공한다. 자동 머지하지 않는다.

## 제외와 운영 준비

소개 페이지, 실제 LDAP 연동, 이메일·OAuth, 회비 결제, 일정 예약, 채팅, 출석, 자동 랭킹, 사진 업로드, 알림 발송은 만들지 않는다.

도메인·호스팅 계정은 아직 연결되지 않았다. 외부 운영 배포는 실제 HTTPS 도메인과 영구 디스크 서버를 정한 뒤 진행하며, 현재 완료 여부와 구별해 보고한다.
