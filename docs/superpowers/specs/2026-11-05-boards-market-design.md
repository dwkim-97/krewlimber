# 공지사항과 포인트 마켓

## 목적

회원 전용 사이트에 일반 게시판 형태의 공지사항과 쇼핑몰 형태의 포인트 마켓을 추가한다. 기존 승인·관리자 권한, 간결한 한국어 UI, 원본 로고와 춘식이 이미지를 유지한다.

## 접근 방식

기존 React·Express·SQLite 안에 화면·보호된 API·추가 마이그레이션을 구현한다. 외부 게시판이나 결제 서비스를 붙이면 별도 로그인과 동호회 권한을 맞춰야 하므로 기존 구조를 확장한다.

## 공지사항

- 승인 회원 열람, 운영진 작성·수정·삭제. 상단 고정 지원.
- 번호·제목·작성자·작성일·조회수 목록, 검색과 페이지 이동, 제목 클릭 시 본문 상세.
- 제목 최대 120자, 본문 최대 4,000자. 본문은 일반 텍스트와 줄바꿈으로 표시해 저장된 HTML 실행을 막는다.
- 모바일은 제목과 날짜를 우선하며 작성·삭제 실패나 없는 글을 명확히 안내한다.
- 운영진 작업은 기존 감사 기록에 남긴다. 기존 회원·세션·타이틀·업적 데이터를 보존한다.

## 포인트 마켓

- 승인 회원에게 카테고리·검색·상품 카드와 상품 상세를 제공한다. 운영진이 상품을 관리한다.
- 상품 이름·이미지·포인트 가격·재고를 쇼핑몰 형태로 표시한다. 이미지가 없으면 상품 분류에 맞는 대체 그림을 사용한다.
- 사용자가 운영진 포인트 지급·회원 상품 교환·운영진 처리까지 구현하는 방식을 선택했다.
- 운영진이 사유와 함께 포인트를 지급하거나 정정한다. 잔액은 거래 원장의 합계이며 음수 정정으로 잔액이 0 미만이 되면 거부한다. 자동 활동 적립은 추가하지 않는다.
- 회원은 한 번에 1~20개 교환 신청한다. 신청 즉시 잔액·재고를 한 트랜잭션에서 차감하고, 처리 대기 상태가 된다. 요청 ID 재전송은 같은 신청을 반환해 중복 차감을 막는다.
- 본인 또는 운영진이 대기 신청을 취소하면 재고·포인트를 한 번만 반환한다. 운영진이 완료한 신청은 취소할 수 없다. 운영진은 대기→완료/취소만 처리한다.
- 포인트 지급·정정에도 작업 ID를 부여하고 같은 운영진의 동일 작업 재시도는 한 번만 반영한다.
- 회원 신청은 화면에서 확인한 상품 revision이 일치할 때만 차감한다. 가격·재고가 달라졌으면 새 내용을 확인한 뒤 다시 신청한다.
- 상품 변경·교환 신청·취소 시 상품 revision을 증가시킨다. 운영진 저장은 읽었던 revision이 일치할 때만 허용하여 동시 교환으로 바뀐 재고를 덮어쓰지 않는다.
- 재고 정정은 대기 신청의 예약 수량을 포함해 최대 1,000,000개 범위를 지킨다. 취소 시 재고 반환을 막는 정정은 거부한다.
- 상품 가격·이름·이미지는 신청 당시 값을 보존한다. 판매 중지는 상품을 비활성화하며 기존 신청은 유지한다. 상품 이미지는 HTTPS 또는 사이트 내부 경로만 허용하며 부재는 null이다.
- 회원은 내 잔액·최근 포인트 내역·교환 내역을 보고, 운영진은 상품·지급·교환 처리를 관리한다. 기본 상품/포인트는 실제 회원 DB에 자동 생성하지 않는다.

## 검증

비회원·미승인 회원 접근, 일반 회원의 관리자 API 호출, 입력 검증, 검색·페이지 이동·삭제·고정 순서, 마이그레이션 데이터 보존을 테스트한다. 거래를 구현하면 잔액·재고 부족과 중복 요청·중복 환불도 검증한다. 예시 데이터는 기존 임시 테스트 DB에만 명시적으로 추가한다.
