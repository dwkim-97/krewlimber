# KREWLIMBER

사내 비공개 클라이밍 동호회 크루라이머의 회원 전용 사이트. 이메일·OAuth·실제 LDAP 연동 없이 `aiden.dw` 같은 사이트 자체 아이디와 비밀번호를 사용합니다.

## 기능

- 소개 페이지 없이 로그인으로 시작하는 회원 전용 베이스캠프
- 아이디·비밀번호 가입과 로그인, 운영진 승인 대기
- 승인된 회원만 조회 가능한 회원 목록, 닉네임 검색·난이도 필터
- 내 프로필·가입 상태·비밀번호 관리
- 분기별 참여·번개 개최·색상별 완등 1위 타이틀, 공동 순위와 과거 분기 조회
- 누적 기록 기반 업적 목록과 대표 업적 선택, 멤버 이름 옆 타이틀과 이름 아래 대표 업적
- 운영진의 분기 기록 입력과 업적 정의 추가·삭제
- 공지사항 목록·상세·검색·고정 및 운영진 작성·수정·삭제
- 상품 카드·상세·포인트 교환 신청과 내 잔액·포인트·교환 내역
- 운영진의 상품·재고·판매 상태, 포인트 지급·정정과 교환 완료·취소 관리
- 운영진의 회원 승인·반려·정지·권한 변경과 변경 이력
- 운영진 신원 확인 후 일회용 복구 코드로 비밀번호 재설정

## 로컬 실행

Node 22.13 이상(운영은 Node 24 권장), pnpm 10을 사용합니다.

```sh
pnpm install
cp deploy/.env.local.sample deploy/.env.local
pnpm dev
```

주소: http://localhost:4173. `HOST=127.0.0.1`, `APP_ORIGIN=http://localhost:4173`가 기본입니다. 접속 주소와 APP_ORIGIN이 정확히 일치해야 변경 요청을 허용합니다. 회원 데이터는 `data/krewlimber.sqlite`에 영구 저장되며 Git에 포함하지 않습니다.

`PHASE`로 `deploy/.env.local`, `deploy/.env.production` 등 환경 파일을 선택합니다. 서버와 관리자 생성 명령은 같은 선택 규칙을 사용하며, NODE_ENV=production이면 기본으로 deploy/.env.production을 읽습니다. 외부에서 지정한 환경변수가 파일 값보다 우선합니다.

## 첫 관리자

기본 계정이나 기본 비밀번호는 없습니다. 터미널에서 다음 명령을 실행하고 아이디·닉네임·비밀번호를 입력하세요. 비밀번호는 화면과 명령 인자에 노출되지 않습니다. 일반 가입은 항상 회원·승인 대기로 생성됩니다.

```sh
pnpm admin:create
```

운영 환경 파일을 사용하는 직접 실행에서는 `NODE_ENV=production pnpm admin:create`로 실행합니다. 기존 회원과 다른 미사용 아이디로 생성합니다. 첫 관리자로 로그인한 후 일반 계정을 승인하거나 관리자로 변경할 수 있습니다. 마지막 관리자의 강등·정지는 거부됩니다.

비밀번호 분실 회원은 운영진에게 별도로 연락합니다. 운영진이 본인을 확인한 뒤 회원 관리의 열쇠 버튼으로 복구 코드를 발급해 본인에게 전달합니다. 회원은 로그인 화면의 `비밀번호를 잊으셨나요?`에서 아이디, 코드, 새 비밀번호를 입력합니다. 코드는 30분 내 한 번만 사용 가능하며 재발급 시 이전 코드는 무효화됩니다.

## 운영 배포

지속적으로 켜져 있는 Node 서버와 영구 디스크가 필요합니다. 정적 GitHub Pages나 임시 파일시스템 서버리스 호스팅에는 사용할 수 없습니다. 현재 저장소에는 외부 서비스 계정이나 도메인이 연결되어 있지 않습니다.

1. 도메인의 HTTPS를 처리하는 리버스 프록시와 영구 디스크가 있는 서버를 준비합니다.
2. 운영 환경에 APP_ORIGIN(실제 HTTPS 출처)과 TRUST_PROXY(백엔드가 관측하는 실제 프록시 IP 또는 CIDR)를 설정한 뒤 `docker compose up --build -d`로 실행합니다. 운영 서버는 TRUST_PROXY 누락 시 시작하지 않습니다. 전체 주소를 신뢰하도록 설정하지 말고, 프록시가 외부의 X-Forwarded-For 값을 덮어쓰거나 올바르게 추가하도록 구성합니다.
3. 프록시의 목적지를 `127.0.0.1:4173`으로 지정합니다. 해당 포트는 인터넷에 직접 노출하지 않습니다.
4. `docker compose exec web node --import tsx scripts/create-admin.ts`로 첫 관리자를 생성합니다.
5. 가입·승인·회원 목록 조회·로그아웃을 실제 HTTPS 주소에서 확인합니다.

운영 모드는 HTTPS APP_ORIGIN을 필수로 하며 Secure/HttpOnly/SameSite 세션 쿠키를 사용합니다. 인증·권한 검증은 서버에서 수행하고 비밀번호는 개별 salt와 scrypt(N=32768,r=8,p=3)로 해시합니다. 세션·복구 코드는 해시만 DB에 저장합니다. 비밀번호 변경·복구 시 모든 세션을 삭제하며, 정지나 권한 변경 시 기존 세션도 폐기합니다. 변경 요청은 APP_ORIGIN과 Origin 헤더를 대조합니다.

단일 서버·단일 프로세스 운영을 전제로 합니다. 지정한 프록시만 신뢰해 원본 클라이언트 IP로 로그인·가입 제한을 분리합니다. 비밀번호 변경 시도는 로그인한 계정별로 제한합니다. 회사 NAT처럼 원본 공인 IP 자체가 같은 사용자는 IP 제한을 공유하므로 운영 정책에 맞춰 가입 제한(기본 IP당 시간당 5회)과 로그인 실패 제한(IP당 15분에 15회)을 조정할 수 있습니다. 여러 인스턴스로 확장할 때는 공유 DB와 공유 제한 저장소가 필요합니다.

## 백업

SQLite DB와 WAL 파일은 함께 일관성을 보장해야 합니다. 실행 중 DB 파일만 복사하지 말고 SQLite의 `.backup` 기능이나 서버를 중지한 상태의 볼륨 스냅샷을 사용합니다. 복구 후 로그인 세션·복구 코드를 폐기하고, 별도 환경에서 복원과 회원 조회를 검증하세요. DB에는 개인정보와 비밀번호 해시가 있으므로 백업도 접근을 제한합니다.

## 구조

`src/pages` 화면, `src/components` 공통 UI, `src/hooks` 로그인·조회 상태, `src/apis` API 클라이언트, `src/types` 공유 타입, `src/consts` 표시 상수, `server` 인증·권한·DB, `scripts` 관리자 생성, `tests` API 통합 테스트.

로고와 춘식이 이미지는 제공받은 원본을 수정하지 않고 사용합니다. 파비콘에는 이미지 1을, 가입·로그인·베이스캠프 화면과 OG 및 소셜 공유 메타 태그에는 이미지 2를 사용합니다. 공유 이미지의 절대 주소는 서버 시작 시 APP_ORIGIN을 기준으로 설정됩니다. 글꼴은 Google Fonts를 사용하며 네트워크에 접근할 수 없으면 시스템 글꼴로 표시합니다.

## 타이틀과 업적

명예의 전당은 분기별 클라이밍 참여·번개 개최/참여·더클라임 빨강/핑크/보라/회색 완등·포인트 순획득/실사용 1위를 계산합니다. 보라 타이틀은 ‘보라 클래스’, 회색은 ‘세계관 최강자’, 번개 참여는 ‘번개 붙박이’, 포인트는 ‘포인트 채굴왕’과 ‘마켓 큰손’입니다. 동률은 공동 보유자로 표시하며 0건과 비활성 회원은 제외합니다. 멤버 카드에는 한국 시간 기준 현재 분기 타이틀을 표시하고 과거 분기는 명예의 전당에서 조회합니다.

내 정보의 업적은 전체 분기 기록을 누적해 달성을 계산합니다. 달성한 업적 하나를 대표로 고르거나 해제할 수 있습니다. 기록 정정으로 조건을 잃거나 정의가 삭제되면 대표 선택도 해제됩니다. 운영진은 크루 관리의 분기 기록과 업적 관리에서 수치·조건을 관리합니다. 활동 이벤트를 자동 수집하는 기능은 아직 연결하지 않았습니다. 기존 자유 형식 성과 데이터와 API는 보존하며 새 화면은 분기 타이틀을 사용합니다.

## 테스트 유저

`server/demo-fixtures.ts`에 관리자·복수 타이틀·공동 1위·대표 업적만 보유·대표 미선택·미획득·승인 대기·정지 등 10개 예시 계정이 정의되어 있습니다. 기본 비밀번호는 테스트 전용 `Krew-Test-2026!`이며 기존 계정의 비밀번호·역할·가입 상태·세션은 덮어쓰지 않습니다.

`DEMO_DATABASE_PATH`를 명시하고 `pnpm demo:seed`를 실행합니다. 대상은 운영 모드가 아닌 OS 임시 디렉터리의 `krewlimber-preview.<문자열>/test.sqlite` 또는 `demo.sqlite`로 제한합니다. 일반 회원 DB와 운영 모드에서는 실행을 거부하며 서버 시작 시 자동 실행하지 않습니다. 반복 실행하면 데모 프로필·분기 기록·대표 선택을 예시 값으로 갱신합니다.

## 공지사항과 포인트 마켓

공지사항은 승인 회원만 읽고 운영진이 관리합니다. 일반 텍스트 본문, 상단 고정, 제목·내용 검색과 페이지 이동을 지원합니다. 작성·수정·삭제는 감사 기록에 남습니다.

포인트는 운영진이 사유와 함께 지급하거나 정정합니다. 가입 시 기본 포인트나 자동 활동 적립은 없습니다. 회원이 교환을 신청하면 포인트와 재고가 즉시 차감됩니다. 처리 대기 중에는 본인 또는 운영진이 취소할 수 있으며 포인트·재고를 한 번만 반환합니다. 완료 후 취소는 거부됩니다. 기존 교환 내역에는 신청 당시 상품 이름·가격·이미지가 보존됩니다.

동일한 신청 ID의 재전송은 원래 결과를 반환합니다. 포인트 지급·정정도 같은 작업 ID의 재시도는 한 번만 반영합니다. 회원이 확인한 상품 버전과 현재 값이 다르면 차감 없이 다시 확인하도록 안내합니다. 포인트 원장·재고·신청·감사 기록은 하나의 SQLite 트랜잭션으로 처리합니다. 운영진이 재고를 정정할 때도 대기 신청의 예약 수량을 포함해 최대 1,000,000개를 넘지 않도록 해 취소 시 반환을 보장합니다. 상품 변경과 교환·취소는 상품 버전을 갱신합니다. 오래된 관리자 편집은 저장을 거부해 동시 교환으로 바뀐 재고가 덮어써지지 않도록 합니다. 상품 이미지는 HTTPS 또는 사이트 내부 경로를 쓰며, 없으면 분류별 대체 그림을 표시합니다.

테스트 상품·공지·포인트·신청 예시는 기존 임시 테스트 계정을 만든 뒤 `DEMO_DATABASE_PATH`를 지정하고 `pnpm demo:boards`로 추가합니다. `demo:seed`와 같은 임시 DB 경로 제한을 적용하며 운영 모드는 거부합니다. 반복 실행해도 이미 변경한 상품·포인트 잔액·교환 내역을 초기화하지 않습니다.

운영진은 마켓 상단의 상품 등록과 상품 상세의 상품 수정에서 이미지 파일과 판매 상태를 관리할 수 있습니다. 판매 중지 상품은 회원 목록에서 숨겨지며 크루 관리의 마켓 관리에서 다시 판매할 수 있습니다. JPG·PNG·WebP(최대 5MB, 2,500만 화소)를 선택하면 미리보기를 표시하고 저장 시 서버에 업로드합니다. 서버는 긴 변 최대 1800px WebP로 다시 저장하며, 이미지 조회에도 승인 회원 권한을 검사합니다.

업로드 파일 저장 위치는 `UPLOADS_DIR`로 지정합니다. 기본값은 `DATABASE_PATH` 파일과 같은 디렉터리의 `uploads`이며, 기존 Docker 영구 볼륨 `/app/data`에 함께 저장됩니다. 운영 서버에 옮길 때 SQLite DB와 uploads 디렉터리를 함께 이전·백업해야 합니다. DB만 복구하면 상품 이미지는 복구되지 않습니다. 기존 교환 내역의 이미지 보존을 위해 업로드 파일은 자동 삭제하지 않습니다.

포인트 순획득은 지급액에서 차감 정정을 뺀 값이며 환불은 획득으로 세지 않습니다. 실사용은 취소되지 않은 교환의 신청 당시 포인트 합계이고 한국 시간의 신청 분기에 귀속됩니다. 나중에 취소하면 과거 분기에서도 해당 사용액을 제외합니다. 포인트 지표는 수동 활동 기록으로 입력할 수 없습니다.

번개 참여 업적은 50회·100회, 포인트 순획득과 실사용은 각각 누적 1,000·5,000·10,000P 기본 업적을 제공합니다. 기존 활동 업적과 합쳐 기본 15개입니다. 운영진은 업적 관리의 ‘조건 수정’에서 설명과 목표 수량을 변경할 수 있습니다. 정정·취소·목표 상향으로 조건을 잃으면 대표 선택이 해제되며, 다시 달성해도 자동으로 대표가 되지 않습니다. DB 버전 6 확장은 기존 기록·업적 순서·대표 선택을 보존하고 새 업적만 추가합니다.
