# KREWLIMBER

사내 비공개 클라이밍 동호회 크루라이머의 회원 전용 사이트. 이메일·OAuth·실제 LDAP 연동 없이 `aiden.dw` 같은 사이트 자체 아이디와 비밀번호를 사용합니다.

## 기능

- 소개 페이지 없이 로그인으로 시작하는 회원 전용 베이스캠프
- 아이디·비밀번호 가입과 로그인, 운영진 승인 대기
- 승인된 회원만 조회 가능한 회원 목록, 닉네임 검색·난이도 필터
- 내 프로필·가입 상태·비밀번호 관리
- 승인된 회원만 볼 수 있는 명예의 전당과 운영진의 기록 등록·삭제
- 운영진의 회원 승인·반려·정지·권한 변경과 변경 이력
- 운영진 신원 확인 후 일회용 복구 코드로 비밀번호 재설정

## 로컬 실행

Node 22.13 이상(운영은 Node 24 권장), pnpm 10을 사용합니다.

```sh
pnpm install
cp deploy/.env.local.sample deploy/.env.local
pnpm dev
```

주소: http://localhost:4173. `HOST=127.0.0.1`, `APP_ORIGIN=http://localhost:4173`가 기본입니다. 접속 주소와 APP_ORIGIN이 정확히 일치해야 변경 요청을 허용합니다. 회원 데이터는 `data/krewlimber.sqlite`에 영구 저장되며 Git에 포함하지 않습니다.

`PHASE`로 `deploy/.env.local`, `deploy/.env.production` 등 환경 파일을 선택합니다. 서버와 관리자 생성 명령은 같은 선택 규칙을 사용하며, NODE_ENV=production이면 기본으로 deploy/.env.production을 읽습니다. 외부에서 지정한 환경변수가 파일 값보다 우선합니다.

## 첫 관리자

기본 계정이나 기본 비밀번호는 없습니다. 터미널에서 다음 명령을 실행하고 아이디·닉네임·비밀번호를 입력하세요. 비밀번호는 화면과 명령 인자에 노출되지 않습니다. 일반 가입은 항상 회원·승인 대기로 생성됩니다.

```sh
pnpm admin:create
```

운영 환경 파일을 사용하는 직접 실행에서는 `NODE_ENV=production pnpm admin:create`로 실행합니다. 기존 회원과 다른 미사용 아이디로 생성합니다. 첫 관리자로 로그인한 후 일반 계정을 승인하거나 관리자로 변경할 수 있습니다. 마지막 관리자의 강등·정지는 거부됩니다.

비밀번호 분실 회원은 운영진에게 별도로 연락합니다. 운영진이 본인을 확인한 뒤 회원 관리의 열쇠 버튼으로 복구 코드를 발급해 본인에게 전달합니다. 회원은 로그인 화면의 `비밀번호를 잊으셨나요?`에서 아이디, 코드, 새 비밀번호를 입력합니다. 코드는 30분 내 한 번만 사용 가능하며 재발급 시 이전 코드는 무효화됩니다.

## 운영 배포

지속적으로 켜져 있는 Node 서버와 영구 디스크가 필요합니다. 정적 GitHub Pages나 임시 파일시스템 서버리스 호스팅에는 사용할 수 없습니다. 현재 저장소에는 외부 서비스 계정이나 도메인이 연결되어 있지 않습니다.

1. 도메인의 HTTPS를 처리하는 리버스 프록시와 영구 디스크가 있는 서버를 준비합니다.
2. 운영 환경에 APP_ORIGIN(실제 HTTPS 출처)과 TRUST_PROXY(백엔드가 관측하는 실제 프록시 IP 또는 CIDR)를 설정한 뒤 `docker compose up --build -d`로 실행합니다. 운영 서버는 TRUST_PROXY 누락 시 시작하지 않습니다. 전체 주소를 신뢰하도록 설정하지 말고, 프록시가 외부의 X-Forwarded-For 값을 덮어쓰거나 올바르게 추가하도록 구성합니다.
3. 프록시의 목적지를 `127.0.0.1:4173`으로 지정합니다. 해당 포트는 인터넷에 직접 노출하지 않습니다.
4. `docker compose exec web node --import tsx scripts/create-admin.ts`로 첫 관리자를 생성합니다.
5. 가입·승인·회원 목록 조회·로그아웃을 실제 HTTPS 주소에서 확인합니다.

운영 모드는 HTTPS APP_ORIGIN을 필수로 하며 Secure/HttpOnly/SameSite 세션 쿠키를 사용합니다. 인증·권한 검증은 서버에서 수행하고 비밀번호는 개별 salt와 scrypt(N=32768,r=8,p=3)로 해시합니다. 세션·복구 코드는 해시만 DB에 저장합니다. 비밀번호 변경·복구 시 모든 세션을 삭제하며, 정지나 권한 변경 시 기존 세션도 폐기합니다. 변경 요청은 APP_ORIGIN과 Origin 헤더를 대조합니다.

단일 서버·단일 프로세스 운영을 전제로 합니다. 지정한 프록시만 신뢰해 원본 클라이언트 IP로 로그인·가입 제한을 분리합니다. 비밀번호 변경 시도는 로그인한 계정별로 제한합니다. 회사 NAT처럼 원본 공인 IP 자체가 같은 사용자는 IP 제한을 공유하므로 운영 정책에 맞춰 가입 제한(기본 IP당 시간당 5회)과 로그인 실패 제한(IP당 15분에 15회)을 조정할 수 있습니다. 여러 인스턴스로 확장할 때는 공유 DB와 공유 제한 저장소가 필요합니다.

## 백업

SQLite DB와 WAL 파일은 함께 일관성을 보장해야 합니다. 실행 중 DB 파일만 복사하지 말고 SQLite의 `.backup` 기능이나 서버를 중지한 상태의 볼륨 스냅샷을 사용합니다. 복구 후 로그인 세션·복구 코드를 폐기하고, 별도 환경에서 복원과 회원 조회를 검증하세요. DB에는 개인정보와 비밀번호 해시가 있으므로 백업도 접근을 제한합니다.

## 구조

`src/pages` 화면, `src/components` 공통 UI, `src/hooks` 로그인·조회 상태, `src/apis` API 클라이언트, `src/types` 공유 타입, `src/consts` 표시 상수, `server` 인증·권한·DB, `scripts` 관리자 생성, `tests` API 통합 테스트.

로고는 제공받은 SVG 원본을 수정하지 않고 사용합니다. 화면의 클라이밍 그래픽은 사이트에서 작성한 SVG입니다. 글꼴은 Google Fonts를 사용하며 네트워크에 접근할 수 없으면 시스템 글꼴로 표시합니다.
